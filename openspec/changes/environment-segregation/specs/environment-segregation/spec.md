# Specification: Environment Segregation

## Requirement 1: Configurable Environment Context
1. The application SHALL read `APP_ENV` (or `ENVIRONMENT`) from the environment, defaulting to `"local"`.
2. Standard normalized values:
   - Production: `"production"`, `"prod"`, `"server"` -> normalized to `"prod"` for key prefixes.
   - Development / Local: `"local"`, `"dev"`, `"development"`, `"staging"`.

## Requirement 2: Isolated Redis Key Namespaces
1. All Redis keys generated by `redis_client.py` SHALL use the configured prefix `REDIS_KEY_PREFIX` or `screener:<normalized_env>`.
2. Schema:
   - Trade Ledger: `{prefix}:extreme_trades`
   - HTF Cache: `{prefix}:htf_cache:{symbol}:{mode}`
   - Alert Deduplication: `{prefix}:alert:{symbol}:{event}:{trade_id}`
   - Runtime Config: `{prefix}:config`

## Requirement 3: Telegram Alert Isolation
1. If `TELEGRAM_ENABLED` is explicitly `"false"`, no Telegram alerts SHALL be sent.
2. In non-production environments (`APP_ENV` not in `("production", "prod", "server")`):
   - Outgoing Telegram alert messages SHALL include a clear prefix tag (e.g. `[DEV]` or `[LOCAL]`).
   - If `TELEGRAM_CHAT_ID_DEV` or `TELEGRAM_CHAT_ID_LOCAL` is provided, alerts SHALL route to the dev chat ID instead of the production chat ID.

## Requirement 4: Local Storage File Isolation
1. `ExtremeTradeTracker` default storage path SHALL be `data/extreme_live_trades_{env}.json` when running in local/dev environments and `data/extreme_live_trades.json` in production, unless overridden by `EXTREME_LIVE_TRADES_FILE`.
